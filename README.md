# دليل المقاسات لمنتجات سلة

تطبيق لإنشاء جدول مقاسات مستقل لكل منتج، وإدارته داخل لوحة سلة، وعرضه للعميل من زر في صفحة المنتج.

ابدأ بـ [قائمة ملفات GitHub](GITHUB_FILES_AR.md)، ثم [خطوات التفعيل داخل سلة](EMBEDDED_SETUP_AR.md).

## الوظائف

- ستة تصاميم للزر، وخمسة خيارات ألوان، ونص موحد اختياري، ومعاينة مباشرة وحفظ خاص بكل متجر.
- ربط المتجر عبر `app.store.authorize` في النمط السهل.
- مزامنة المنتجات والصور وSKU وحالة العرض والبحث في الكتالوج.
- محرر صفوف وأعمدة للمقاسات، ووحدات سم/إنش، وقياسات الجسم أو القطعة.
- مسودات ومعاينة ونشر ونسخ جدول منتج آخر وإيقاف الظهور.
- لوحة مضمنة داخل سلة بدخول موثق خاص بكل متجر، مع ثيم فاتح وداكن وخط PingARLT.
- مدخل مستقل للمسؤول عند `/dashboard` بكلمة المرور الحالية.
- عرض النسخة المنشورة فقط للمنتجات الظاهرة في المتجر.

## البيئة والنشر

| المتغير | الاستخدام |

| `DATABASE_URL_UNPOOLED` | اختياري؛ اتصال مباشر لتهيئة جدول المتاجر |
| `SALLA_WEBHOOK_SECRET` | مفتاح حماية Webhook بوضع Token |

آلية OAuth المخصصة لربط سلة تستخدم `SALLA_CLIENT_ID` و`SALLA_CLIENT_SECRET` و`SALLA_REDIRECT_URI` عند اختيار ذلك النمط. تظل جزءًا من ربط المتجر، ولا تُطلب للنمط السهل.

أمر البناء في Render:

```bash
pip install -r requirements.txt
```

أمر التشغيل:

```bash
uvicorn main:app --host 0.0.0.0 --port $PORT
```

ضع الملفات في جذر المستودع واترك Root Directory فارغًا. احتفظ بالأسرار في Render ولا ترفعها إلى GitHub.

## ربط الصفحة المضمنة

| الحقل | القيمة |
|---|---|
| مسار الصفحة | `size-guide` |
| رابط Iframe | `https://salla-pageindex-api.onrender.com/salla/embedded` |
| الصفحة الافتراضية | مفعّل إذا ظهر الخيار |

افتح التطبيق من التطبيقات المثبتة داخل لوحة المتجر بعد النشر. الرابط المضمن المباشر يحتاج جلسة ترسلها سلة.

## ربط المتجر وزر المنتج

اختر Easy Mode وحماية Token، واستخدم رابط التنبيهات `https://salla-pageindex-api.onrender.com/webhook`.

بعد تثبيت التطبيق أو إعادة إرسال التفويض، زامن المنتجات وأنشئ الجدول وانشره. من «تركيب زر المتجر» انسخ JavaScript الخاص بالمتجر إلى App Snippets. تحميل الملف عبر ربط Google Tag Manager المتاح للمتجر مسار بديل يحتاج اختبارًا منفصلًا.

يظهر الزر لمنتج له جدول منشور في الموضع الذي تختاره من إعدادات الزر. الموضع الافتراضي فوق السعر. يبقى السنيبت العامل الحالي كما هو؛ لا يحتاج تحديث المظهر إلى إعادة التثبيت أو تعديل السنيبت.

تضمين لوحة التاجر لا يحمّل الزر في واجهة العملاء تلقائيًا. يلزم بقاء كود تركيب الزر محملًا في واجهة المتجر. بعد تحديث التطبيق لا تحتاج تغيير هذا الكود عند تغيير التصميم أو الألوان.

## استوديو الزر: 12 تصميمًا و15 موضعًا

افتح **إعدادات الزر** داخل التطبيق. اختيار الشكل مستقل عن المكان وعن ألوان الهوية.

### التصاميم

رابط أنيق، إطار رفيع، ممتلئ، الكبسولة الداكنة، لمسة ناعمة، إطار متقطع، زر مقسوم، شريط إرشادي، بطاقة القياس، أيقونة دائرية، صف بسهم، مربع عمودي.

### المواضع

- داخل التفاصيل: فوق السعر، تحت السعر، تحت اسم المنتج، قبل الخيارات، بجانب عنوان المقاس، فوق زر السلة، بجانب زر السلة.
- على الصورة الرئيسية: أعلى اليمين، أعلى اليسار، أسفل اليمين، أسفل اليسار.
- ثابتة على الشاشة: عائم أسفل اليمين، عائم أسفل اليسار، لسان جانبي، شريط للجوال.

يمكن اختيار موضع مختلف للجوال (حتى 767px)، أو إبقاء نفس اختيار الكمبيوتر. اختيار «شريط ثابت للجوال» يستخدم موضع فوق السعر على الكمبيوتر. مواضع الشاشة تدعم safe-area، ويمكن ضبط المسافة عن الحافة (0–48px) والارتفاع عن الأسفل (0–240px). يبدأ الارتفاع الجديد من 88px؛ راجعه مع شريط الشراء الثابت في الثيم.

المعاينة تستخدم نفس راسم الزر ومحرك المواضع اللذين يستخدمهما المتجر، مع عناصر توضيحية للصورة والسعر والمقاسات والسلة. زر الكمبيوتر/الجوال يغيّر جهاز المعاينة فقط ولا يغيّر الإعدادات المحفوظة. المعاينة لا تحفظ تلقائيًا.

### الألوان والتفاصيل

10 مجموعات ألوان: أسود، زمردي، ذهبي، وردي، بيج، كحلي، عنابي، أبيض، بنفسجي، روز. يمكن تخصيص الخلفية والنص والإطار والأيقونة والنص المساعد باستخدام HEX أو منتقي الألوان. تغيير الشكل يحتفظ بالألوان الحالية. يمكن استعادة ألوان الشكل المقترحة من قسم الألوان اليدوية. يوجد تنبيه عند انخفاض تباين اللونين المختارين؛ الخلفيات الفعلية في المتجر قد تختلف.

يمكن اختيار حجم صغير/متوسط/كبير ومحاذاة داخل التفاصيل. مساحة الضغط لا تقل عن 44px، ولتصميم الأيقونة اسم مقروء لقارئات الشاشة. ألوان نافذة جدول المقاسات مستقلة، وتُعدّل داخل محرر المنتج.

### الحفاظ على الإعدادات السابقة

الإعداد القديم `design=floating` يُقرأ كتصميم `pill` مع موضع `floating_left` وارتفاع 24px، مع الاحتفاظ بالألوان والنصوص. باقي التصاميم القديمة دون موضع محفوظ تبدأ فوق السعر، كما في تعديل موضع السعر السابق. تُخزن الحقول الجديدة في JSONB الموجود، بلا تغيير مخطط القاعدة أو حذف الجداول. الحفظ مشروط برقم النسخة لمنع الكتابة فوق تعديل نافذة أخرى.

### توافق الثيم

تحققنا من محددات الثيم التجريبي: السعر `[data-testid="store-product-price"]`، الصورة `[data-testid="store-product-image-slider"] .s-slider-container`، العنوان `[data-testid="store-product-title"]`، وزر السلة `salla-add-product-button[product-id]`. زر الصورة يُوضع داخل الحاوية الثابتة خارج رابط التكبير والشريحة المتحركة.

عند غياب العنصر المطلوب، يُستخدم السعر أو الخيارات أو زر السلة، ثم موضع عائم إذا غابت جميع هذه العناصر. «بجانب عنوان المقاس» يتطلب عنوانًا يمكن التعرف عليه في DOM؛ وإلا يستخدم البديل. لا نفترض دعم المواضع الدقيقة في كل ثيم. المواضع التي تنشئ حاوية بجانب السلة أو عنوان المقاس تنظّف الحاوية وتعيد العنصر عند تغيير الموضع أو التنقل. راجع زوايا الصورة مع زر المفضلة وأزرار تكبير الصور في متجرك.

### التحقق والنشر

اختبارات الإصدار: 52 اختبار Python، واختبارات DOM للتصاميم والمواضع والمعاينة والحفظ والتعارضات وعزل المتاجر والجوال، واختبارات عميل Salla Embedded. الاختبارات تستخدم بيانات وهمية ولا تتصل بقاعدة المتجر. لم يُنشر الإصدار تلقائيًا، ولم يكتمل فحص بصري في متصفح أو على هاتف فعلي قبل التسليم؛ متصفح الفحص يمنع عناوين الملفات المحلية.

بعد النشر راجع منتجًا له جدول منشور على الكمبيوتر والجوال: جرّب فتح النافذة، والسحب بين الصور، وزر السلة، وموضعًا مخصصًا للجوال. لا تحتاج إعادة تثبيت التطبيق أو تغيير السنيبت العامل.

## البيانات

الجداول المستخدمة: `stores` و`dashboard_catalog` و`dashboard_jobs` و`dashboard_login_limits` و`product_size_guides` و`size_guide_button_settings`.

حفظ المسودة لا يغيّر النسخة المنشورة. عمليات التاجر المضمن مقيدة بمتجره على الخادم. تحديث الملفات لا يحذف بيانات المتجر أو جداول المقاسات، ولا ينفّذ إسقاط جداول قاعدة البيانات.

يدعم الجدول حتى 30 مقاسًا و10 أعمدة. أدخل القياسات الفعلية للمنتج؛ الهياكل الفارغة لا تتضمن أرقامًا افتراضية.

## التحقق

```bash
pip install -r requirements.txt httpx
python -m unittest discover -p 'test_*.py' -v
node test_embedded_client.cjs
```

لاختبارات DOM الإضافية استخدم Node `22.22.2` أو أحدث من فرع 22، أو `24.15.0` أو أحدث من فرع 24، أو 26 فأحدث:

```bash
npm install
npm test
```

متطلبات npm خاصة بالاختبارات؛ يبقى بناء Render باستخدام `pip install -r requirements.txt`، والتشغيل بواسطة Uvicorn.

نجح 51 اختبار Python واختبارات JavaScript للتهيئة والتصاميم والألوان والحفظ والمعاينة وحماية التعديلات غير المحفوظة. الاختبارات تحاكي سلة وقاعدة البيانات وDOM؛ لم تُنفّذ تجربة مرئية في متصفح المتجر الفعلي. بعد النشر اختبر الدخول والمزامنة والمسودات والنشر وظهور الجدول في المنتج على الكمبيوتر والجوال.

## حدود التشغيل

- تجديد توكن Merchant API تلقائيًا غير منفّذ؛ أعد إرسال التفويض عند انتهاء صلاحيته.
- المزامنة داخل عملية الخدمة وقد تنقطع عند إعادة النشر.
- تختلف عناصر القالب ومواضع الزر؛ اختبار المتجر الفعلي مطلوب.
- جلسة اللوحة المضمنة مدتها ساعة؛ يظهر تنبيه للتجديد دون إعادة تحميل تلقائية قد تفقد التعديلات.
